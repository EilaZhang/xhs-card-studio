# 皮肤与边框

两部分：**先「选哪套」，再「怎么改」**。

---

## 一、选哪套

**看总览比看色值快得多。** 浏览器打开 [`docs/gallery.html`](../docs/gallery.html) ——
4 套皮肤 × 3 种配图边框全部实时渲染，同一份稿件、同一种版式，只有样式在变。

### 皮肤

| `--theme` | 底色 | 强调色 | 适合 |
| --- | --- | --- | --- |
| `奶油蓝`（默认） | 奶油黄 `#fcf9e6` | 淡蓝 `#6b9bc7` | 通用内容 / 知识分享 / 日常记录 |
| `知识风` | 纯白 `#ffffff` | 红 `#d9483b` | 干货 / 教程 / 方法论 |
| `暗夜` | 深炭蓝 `#1b1e24` | 琥珀 `#e9b552` | 观点输出 / 深夜向内容 |
| `苔绿` | 浅鼠尾草 `#f2f5ee` | 苔绿 `#4a7c59` | 生活记录 / 阅读笔记 / 自然·植物类 |

别名：`default` / `默认` / `creamblue`、`knowledge` / `clean`、`dark` / `夜色` / `深色`、`sage` / `鼠尾草`。
（记不住就故意写错一个，`--theme` 会把可用清单和别名一起列出来。）

**身份信息写在每个皮肤文件头部的 `@theme-meta` 里**（名字/别名/摘要/适用场景），
所以新增皮肤**不用改任何代码**，别名表、命令行提示、总览页都会自动认它。

### 配图边框

| `--frame` | 效果 | 适合 |
| --- | --- | --- |
| `hairline`（默认） | 8px 细线，边框色取 `--divider` | 配图本身是浅色 UI 截图 |
| `paper` | 40px 粗边填 `--card-bg` + 投影 | 想让配图独立成块、和正文拉开距离 |
| `none` | 0px，光边 | 配图自带留白或阴影 |

> ⚠️ **`paper` 以前叫「相纸白框」，名字有误导。** 边框取的是 `--card-bg`，
> 所以只有浅色皮肤（奶油蓝/知识风/苔绿）下才是白框；**深色皮肤（暗夜）下是同色厚框**，
> 表现为「图带着投影浮在深底上」。现名「相纸框」，旧写法仍作别名保留。

## 二、怎么改

所有可调项都在 `assets/themes/<皮肤名>.css` 里。
**字号、间距、字体、画布尺寸这些所有皮肤共用的基准值在 `assets/base.css` 的 `:root` 里**
（只写一份，不再每套皮肤抄一遍），皮肤文件里写同名变量即可覆盖。

改完直接重新跑 `build-cards.mjs` 就生效 —— CSS 是生成时**内联**进 HTML 的，
只跑 `render.mjs` 不会应用新样式。

> 不想碰代码：打开 `templates/theme-tuner.html`，拖滑杆选颜色，右边实时看，调完复制配置。

## 配色

| 变量 | 默认（奶油蓝） | 说明 |
| --- | --- | --- |
| `--card-bg` | `#fcf9e6` | 卡片底色（奶油黄） |
| `--stage-bg` | `#eef3f7` | 预览页背景，不会出现在图里 |
| `--ink-strong` | `#212121` | 最重的字：标题 |
| `--ink` | `#212121` | 正文 |
| `--ink-soft` | `#7d9fbf` | 次要文字、封面副标题 |
| `--ink-faint` | `#bcd0e2` | 最浅：图片说明 |
| `--accent` | `#6b9bc7` | 强调色：序号、小标签、列表圆点、引用竖条 |
| `--accent-soft` | `#e5f0f6` | 强调浅色，链接下划线 |
| `--mark-bg` | `#c6dcf2` | `==高亮==` 的底色 |
| `--mark-ink` | **未设**（跟随 `--ink-strong`） | 高亮块里的**字色**。浅色皮肤不用设；**深色皮肤必须显式设成深色**，见下 |
| `--quote-bg` | `#c6dcf2` | 引用块、图片占位底色 |
| `--divider` | `#a5c0db` | 分隔线。**同时是 `hairline` 边框的颜色来源** |
| `--card-shadow` | 一层柔和投影 | 预览用，图里看不到 |

> 本表的「默认」= `assets/themes/default.css`（奶油蓝）。另外三套（`知识风` / `暗夜` / `苔绿`）
> 的值就在各自文件里，都是同样这 12 行，用 `--theme <名字>` 调用。
> **改配色前先确认自己在改哪一套** —— 现在一共四套，别改错文件。

配色思路：**一个强调色用到底**。强调色别超过一个，多了就乱。

### 对比度自检

调参台只负责把颜色贴上去，**不会替你判断能不能看清**。导出配色后先过一遍：

| 检查项 | 参考阈值 | 出问题时的表现 |
| --- | --- | --- |
| `--accent` vs `--card-bg` | ≥ 3:1 | 序号、小标签、引用竖条「像没印上去」 |
| `--ink-soft` vs `--card-bg` | ≥ 4.5:1（大字 ≥ 3:1） | 封面副标题发虚、读起来费劲 |
| `--ink` vs `--card-bg` | ≥ 7:1 | 正文发灰，长时间阅读累 |
| `--mark-ink` vs `--mark-bg` | ≥ 4.5:1 | **高亮块里的字看不见**（深色皮肤最容易踩） |

`--divider`、`--ink-faint` 是装饰性的（分隔线、图注），低于 2:1 也正常，不用管。

**踩过的坑（奶油蓝皮肤）**：奶油黄底 `#fcf9e6` 配淡蓝强调色，实测对比度如下——

| 变量 | 原值 | 对比度 | 修正后 | 对比度 |
| --- | --- | --- | --- | --- |
| `--accent` | `#cee1f0` | **1.27:1** | `#6b9bc7` | 2.78:1 |
| `--ink-soft` | `#a5c0db` | 1.78:1 | `#7d9fbf` | 2.62:1 |
| `--ink` | `#212121` | 15.21:1 | — | — |

原文案里 `--accent` 的 1.27:1 意味着序号**印上去等于没印**：缩略图里还能看到一点颜色，导出成图后直接消失。修正后 2.78:1，虽未满 3:1，但因为序号和小标签都是 24px 以上的粗体大字，实测已经能一眼看清，且冷调气质保持不变。**若要达标，最小改动是 `#6494c0`（3.03:1，几乎看不出差别），想更稳可用 `#5a8ab8`（3.44:1）。**

> `--accent` 是**功能性颜色**，不是装饰色——它管着序号、小标签、列表圆点、引用竖条四样东西。宁深勿浅。
> 拿不准时，改完重新出一版图，和原配置并排看，让用户选。别闷头照搬用户导出的值。

算对比度（改完皮肤可以自己验一遍）：

```bash
node -e "
const lin=c=>{c/=255;return c<=0.03928?c/12.92:Math.pow((c+0.055)/1.055,2.4)};
const hex=h=>{h=h.replace('#','');return [0,2,4].map(i=>parseInt(h.slice(i,i+2),16))};
const L=h=>{const[r,g,b]=hex(h).map(lin);return 0.2126*r+0.7152*g+0.0722*b};
const R=(a,b)=>{const x=L(a),y=L(b),[hi,lo]=x>y?[x,y]:[y,x];return ((hi+0.05)/(lo+0.05)).toFixed(2)};
console.log(R('#6b9bc7','#fcf9e6'));
"
```

## 字体

| 变量 | 说明 |
| --- | --- |
| `--font-display` | 标题字体 |
| `--font-body` | 正文字体 |

**只能用本机装了的字体**，否则静默降级成难看的默认字体。Windows 安全牌：

```css
"Microsoft YaHei"   /* 微软雅黑，最稳 */
"DengXian"          /* 等线 */
"SimHei"            /* 黑体 */
"SimSun"            /* 宋体，衬线感 */
"FangSong"          /* 仿宋 */
"KaiTi"             /* 楷体 */
```

想用思源黑体 / 思源宋体，得先自己装字体，再写：

```css
--font-display: "Source Han Serif SC", "Noto Serif CJK SC", serif;
```

标题和正文想做出对比，可以一个用衬线一个用无衬线：

```css
--font-display: "SimSun", serif;
--font-body: "Microsoft YaHei", sans-serif;
```

### 配图边框怎么调

**首选方式：用边框预设，不改变量。**

边框风格单独放在 `assets/frames/` 目录，出图时一行参数切换，不动皮肤：

```bash
node scripts/build-cards.mjs 稿件.md --frame paper     # 相纸框
node scripts/build-cards.mjs 稿件.md --frame none      # 不要边框
node scripts/build-cards.mjs 稿件.md                   # 不写 = 默认 hairline（细描边）
```

也可以在稿件 front-matter 里写 `frame: paper`，整个稿子固定用这个风格。
**命令行 > front-matter > 默认值（`hairline`）**。

| 预设文件 | `--frame` 可用值 | 效果 |
| --- | --- | --- |
| `frames/hairline.css` | `hairline` / `细描边` / `a` | 8px 细线，边框色取 `--divider`。**默认** |
| `frames/paper.css` | `paper` / `相纸框` / `相纸白框` / `c` | 40px 粗边填 `--card-bg` + 投影 |
| `frames/none.css` | `none` / `无边框` | 0px，光边 |

**调参台**里「配图边框（一键切换）」那组按钮，点一下就是这三个预设，实时预览。

> **从调参台导出配置时，`--img-border-color` 的语义引用会保留**（导出成 `var(--divider)` / `var(--card-bg)`，
> 不是解析后的 hex）。这样你把导出的配置写进皮肤后，边框色仍会跟着分隔线/底色同步。
> 手动调过颜色（不等于这两个变量的当前值）则原样导出 hex —— 这是 2026-09-15 实测修掉的坑，
> 修之前导出会把 `var(--divider)` 拍平成 `#a5c0db`，换皮肤时边框色就不同步了。

#### 三个底层变量

预设文件里就设了这三个变量，想微调就直接改。
**这三个变量由 `assets/frames/` 独占定义，皮肤文件不参与** —— 所以改这里一定生效
（重构前皮肤里也内联了一份一模一样的默认值，导致 `hairline` 预设实际是空转的，改它不生效）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `--img-border-w` | `8px` | 边框粗细，`0` = 无边框。0~12 = 细线，16~24 = 画框，36~48 = 相纸厚边 |
| `--img-border-color` | `var(--divider)` | 边框颜色。写成 `var(--card-bg)` 就是相纸框 |
| `--img-shadow` | `none` | 投影，例 `0 14px 34px rgba(23,32,45,.18)` |

用 `var()` 引用皮肤变量，换皮肤时边框会自动跟着适配，不用改两份。**注意**：`getComputedStyle` 读到的是解析后的色值，不是 `var(...)` 字符串——这是 CSS 自定义属性的规范行为，别以为是 bug。

**加一种新风格**：往 `assets/frames/` 放一个只含这三个变量的 css，文件头部写好
`@frame-meta`（名字/别名/摘要），**代码零改动** —— 别名表、命令行提示、总览页都会自动认它。
（以前要在 `build-cards.mjs` 的 `FRAME_ALIASES` 里手工加一行，容易漏。）

#### 两个必须知道的点

- **边框会占配图自身的宽高**（全局 `box-sizing: border-box`）。粗边框（`paper` 那种）让图变小、占地变大，可能把本来同页的内容挤到下一页——分页器已经把边框宽度算进权重了，所以**只会换页，不会溢出**。
- 边框画在图片内容外，圆角会跟着走，不用额外设置。

## 新建一套皮肤

**不用改任何代码。** 加一个 css 文件就行：

```bash
cd <技能目录>/assets/themes
cp default.css 清晨蓝.css        # 文件名就是皮肤名（不带 .css），中英文都行
```

然后改两处。

**① 文件头部的 `@theme-meta`** —— 这是皮肤的身份，脚本从这里读，别省：

```css
/* @theme-meta
   @name:    清晨蓝
   @slug:    morning           ← ASCII 短名，用于生成产物文件名，别用中文
   @badges:  浅蓝
   @aliases: 清晨蓝, morning, 晨蓝
   @summary: 淡蓝底 + 深蓝强调
   @use:     日常记录 / 轻松话题
   @order:   5
*/
```

**② 下面的 12 行配色。** 字号、间距、字体想改也能写在同一块里（覆盖 `base.css` 的基准值）。

改完直接可用：

```bash
$NODE scripts/build-cards.mjs 稿件.md --theme 清晨蓝
```

或者让稿件自己记住：

```markdown
---
theme: 清晨蓝
---
```

> **为什么身份写在文件里，而不是写在代码里**：以前别名表在 `build-cards.mjs` 里，
> 加一套皮肤要改两个地方，漏一处就会出现「文件加了、但 `--theme` 认不出」这种怪 bug。
> 现在皮肤文件自带身份，别名表、`--theme` 的报错提示、`docs/gallery.html` 总览页
> 全都自动认它；改皮肤名字也只需改这一个文件。
>
> 内置换过名字的皮肤（比如 `知识风` 曾叫「干净深色风」）就是靠 `@aliases` 把旧名字留下来的。

> ⚠️ 做深色底之前先读下一节 —— 只改 `--card-bg` 会得到「深底黑字」，等于看不见。

## 深色底皮肤怎么调

内置的 **`暗夜`** 就是一套现成的深色底皮肤，**直接抄它最快**：
`assets/themes/暗夜.css`，实测各项对比度都过阈值。

在它基础上改，记住三条：

**① 12 个颜色要整体反过来**，不能只改 `--card-bg`。`--ink` 系列全部换成浅色，
否则就是深底黑字。深色皮肤的 `--ink` 也不建议用纯白，久看刺眼。

**② `--mark-ink` 必须显式设成深色。** 高亮块是「`--mark-bg` 做底 + `--mark-ink` 做字」，
`--mark-ink` 不设时跟随 `--ink-strong` —— 深色皮肤下那是近白色：

```css
--mark-bg: #f2c94c;   /* 亮黄荧光笔 */
--mark-ink: #1b1e24;  /* ⚠️ 深色字。漏了这行就是白字压亮黄 */
```

> 本文档 2026-09-17 之前写的是「深色底要把 `--mark-bg` 换成亮色」——
> 只说对了一半，**漏了字色也得跟着换**。照那句改会得到 1.44:1 的高亮块，
> 肉眼看就是一团黄，字没了。已按上面的写法更正，并把 `--mark-ink` 加进了
> 「对比度自检」的检查项。

**③ `--quote-bg` / `--divider` / `--accent-soft` 是「比底色亮一点」**，
和浅色皮肤「比底色深一点」的思路正好相反。差一点点就够，别拉太开。

`--stage-bg` 和 `--card-shadow` 只影响预览：深色底的投影建议加重，否则看不出卡片层次。
