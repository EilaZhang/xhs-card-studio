# 皮肤与边框

两部分：**先「选哪套」，再「怎么改」**。

## 一、选哪套

**看总览比看色值快得多。** 浏览器打开 [`docs/gallery.html`](../docs/gallery.html) ——
5 套皮肤 × 3 种配图边框全部实时渲染，同一份稿件、同一种版式，只有样式在变。

### 配图边框

| `--frame` | 效果 | 适合 |
| --- | --- | --- |
| `hairline`（默认） | 8px 细线，边框色取 `--divider` | 配图本身是浅色 UI 截图 |
| `paper` | 40px 粗边填 `--card-bg` + 投影 | 想让配图独立成块、和正文拉开距离 |

> 表现为「图带着投影浮在深底上」。现名「相纸框」，旧写法仍作别名保留。

## 二、怎么改

所有可调项都在 `assets/themes/<皮肤名>.css` 里。
**字号、间距、字体、画布尺寸这些所有皮肤共用的基准值在 `assets/base.css` 的 `:root` 里**
（只写一份，不再每套皮肤抄一遍），皮肤文件里写同名变量即可覆盖。

改完直接重新跑 `build-cards.mjs` 就生效 —— CSS 是生成时**内联**进 HTML 的，
只跑 `render.mjs` 不会应用新样式。

> **不想碰代码：** 打开 `templates/theme-tuner.html`，拖滑杆选颜色，右边实时看，调完复制配置。
> 调参台顶部「从哪套皮肤起调」列的就是 `assets/themes/` 下真实存在的皮肤，点一下整套套用。
> 这份清单来自 `templates/tuner-data.js`（**生成物**）—— 加/删皮肤后跑一次
> `node scripts/build-tuner.mjs` 刷新，否则调参台里看不到新皮肤。

| 变量 | 默认（奶油蓝） | 说明 |
| --- | --- | --- |
| `--card-bg` | `#fcf9e6` | 卡片底色（奶油黄） |
| `--ink-strong` | `#212121` | 最重的字：标题 |
| `--ink` | `#212121` | 正文 |

| `--mark-ink` | **未设**（跟随 `--ink-strong`） | 高亮块里的**字色**。浅色皮肤不用设；**深色皮肤必须显式设成深色**，见下 |
| `--quote-bg` | `#c6dcf2` | 引用块、图片占位底色 |
| `--divider` | `#a5c0db` | 分隔线。**同时是 `hairline` 边框的颜色来源** |
| — 以下不在皮肤文件里 — | | |

| `--stage-bg` | `color-mix(in srgb, var(--card-bg) 94%, #000)` | 预览页背景，不会出现在图里。**从卡片底色推**，色相自动跟着皮肤走。**深色皮肤必须覆盖** |
| `--card-shadow` | `0 18px 48px rgba(0,0,0,.12)` | 预览用投影，图里看不到。**深色皮肤必须覆盖**（深底要更重） |

> 本表的「默认」= `assets/themes/default.css`（奶油蓝）。另外四套（`暗夜` / `暮紫` / `普鲁士蓝` / `松墨`）
> 的值就在各自文件里，都是同样这 **9 行**（深色底另加 `--mark-ink` + 两个预览色），
> 用 `--theme <名字>` 调用。**改配色前先确认自己在改哪一套** —— 现在一共五套，别改错文件。
>
> 最后三行为什么不在皮肤里：`--accent-soft` 全仓库只有一处消费（链接下划线）且能算出来；
> `--stage-bg` / `--card-shadow` 只在多卡预览里可见 —— `body.is-single` 会把页面背景
> 换成 `--card-bg`、把投影关掉，导出 PNG 时一定被覆盖。所以它们不是「皮肤的身份色」。
> 深色底必须覆盖后两个的原因写在 `assets/themes/暗夜.css` 文件头 ④（`暮紫.css` / `松墨.css` 同）。

配色思路：**一个强调色用到底**。强调色别超过一个，多了就乱。

### 对比度自检

调参台只负责把颜色贴上去，**不会替你判断能不能看清**（不是做不到，是这一版还没做）。
导出配色后先过一遍：

| 检查项 | 参考阈值 | 出问题时的表现 |
| --- | --- | --- |
| `--accent` vs `--card-bg` | ≥ 3:1 | 序号、小标签、引用竖条「像没印上去」 |
| `--ink-soft` vs `--card-bg` | ≥ 4.5:1（大字 ≥ 3:1） | 封面副标题发虚、读起来费劲 |
| `--ink` vs `--card-bg` | ≥ 7:1 | 正文发灰，长时间阅读累 |
| `--mark-ink` vs `--mark-bg` | ≥ 4.5:1 | **高亮块里的字看不见**（深色皮肤最容易踩） |

> 从配色卡生成皮肤时这套检查**会自动跑**，结果印在报告和草稿文件的头部注释里（见下）。
> 手工改皮肤之后想自己验一遍，直接 import 颜色库，别抄一份公式：
>
> ```bash
> node -e "import('<技能目录>/scripts/lib/color.mjs').then(m=>{
>   console.log(m.contrastOf('#6b9bc7','#fcf9e6'));   // 2.78
> })"
> ```

`--divider`、`--ink-faint` 是装饰性的（分隔线、图注），低于 2:1 也正常，不用管。

#### 先看底色给不给得起（天花板）

上表的阈值不是「努力就能达到」的。**字色能拿到的对比度上限，由底色的相对亮度决定**：

- 深色底（浅色字）：上限 = `1.05 / (亮度 + 0.05)`
- 浅色底（深色字）：上限 = `(亮度 + 0.05) / 0.05`

底色亮度 **0.10 ~ 0.35（中明度）**是死区：浅色字的天花板只有 4.5 ~ 7.0:1，
`--ink` 的 7:1 基本够不到，`--ink-soft` 的 4.5:1 也贴着边。**这不是取色不准，是配色的物理限制** ——
`#71749d`（亮度 0.184）配白字实测 **4.48:1**，怎么调参数都过不了 7:1。

所以自检里要分清两种「没过」：

| 报告写 | 含义 | 该怎么办 |
| --- | --- | --- |
| `⚠️ 不足，还差 x.xx` | 是我们的问题 | 换候选色、改 `--accent` / `--ink` |
| `⚠️ 顶格了（该底色上限 x.xx）` | 换个参数也没用 | 压深底色、放大字号，或换卡 |

从配色卡生成时这两种会自动分开判。真要用中明度底色，**只有两条路**：把底色压深
（报告的告警会直接给出「压到哪个 hex 就够」，比如 `#71749d` → `#545775` 白字刚好 7.01:1），
或者接受「只承载大字」。小红书卡片本来就以大字号为主，`≥3:1` 的大字标准下中明度底色是能用的 ——
但别拿它排小字正文。

**踩过的坑（奶油蓝皮肤）**：奶油黄底 `#fcf9e6` 配淡蓝强调色，实测对比度如下——

| 变量 | 原值 | 对比度 | 修正后 | 对比度 |
| --- | --- | --- | --- | --- |
| `--accent` | `#cee1f0` | **1.27:1** | `#6b9bc7` | 2.78:1 |
| `--ink-soft` | `#a5c0db` | 1.78:1 | `#7d9fbf` | 2.62:1 |
| `--ink` | `#212121` | 15.21:1 | — | — |

原文案里 `--accent` 的 1.27:1 意味着序号**印上去等于没印**：缩略图里还能看到一点颜色，导出成图后直接消失。修正后 2.78:1，虽未满 3:1，但因为序号和小标签都是 24px 以上的粗体大字，实测已经能一眼看清，且冷调气质保持不变。**若要达标，最小改动是 `#6494c0`（3.03:1，几乎看不出差别），想更稳可用 `#5a8ab8`（3.44:1）。**

> `--accent` 是**功能性颜色**，不是装饰色——它管着序号、小标签、列表圆点、引用竖条四样东西。宁深勿浅。
> 拿不准时，改完重新出一版图，和原配置并排看，让用户选。别闷头照搬用户导出的值。

算对比度（改完皮肤可以自己验一遍）：

```bash
node -e "
const lin=c=>{c/=255;return c<=0.03928?c/12.92:Math.pow((c+0.055)/1.055,2.4)};
const hex=h=>{h=h.replace('#','');return [0,2,4].map(i=>parseInt(h.slice(i,i+2),16))};
const L=h=>{const[r,g,b]=hex(h).map(lin);return 0.2126*r+0.7152*g+0.0722*b};
const R=(a,b)=>{const x=L(a),y=L(b),[hi,lo]=x>y?[x,y]:[y,x];return ((hi+0.05)/(lo+0.05)).toFixed(2)};
console.log(R('#6b9bc7','#fcf9e6'));
"
```

### 从配色卡图片起一套皮肤

手里有一张配色卡时，别对着屏幕目测，也别手工拼 9 个变量：

```bash
node scripts/palette-from-image.mjs 色卡.png                  # 出清单 + 派色 + 自检（不落盘）
node scripts/palette-from-image.mjs 色卡.png --write          # 再落一份草稿到 assets/themes/_draft/
node scripts/palette-from-image.mjs 色卡.png --bg 1 --accent 3 --write   # 角色猜错了就手工指认
node scripts/palette-from-image.mjs 色卡.png --print-only     # 只到候选清单就停
```

草稿落在 `assets/themes/_draft/<slug>.css`，头部 `@theme-meta` 已写好，确认后一条 `mv` 就启用。
放 `_draft/` 是刻意的：模板清单只认顶层 `*.css`，子目录天然被忽略 —— 草稿不会混进
`--theme` 的可选清单，也不触发预览图的 README 反查告警。

#### 9 个槽位怎么派

只有 **3 个是直取**（`card-bg` / `ink-strong` / `accent`），其余 6 个由这三个派生。
报告里每条值都标了来源，越靠后越不可信：`指定` > `直取` > `派生` > `兜底`。

| 槽位 | 规则 | 依据 |
| --- | --- | --- |
| `--card-bg` | `--bg`，否则占比最大的候选 | 占比 <50% 会告警 |
| `--ink-strong` | `--ink`，否则「对比 ≥7:1 且饱和度 <0.35」里占比最大的 | 4 套皮肤全部命中 |
| `--accent` | `--accent`，否则「对比 ≥3:1 且饱和度 ≥0.15」里最艳的；同档取最深的 | 见下「两个坑」 |
| `--mark-bg` | 能直取就直取（卡里最艳、且不暗于强调色）；否则 accent 提亮 | 4/4 套里高亮块都是最艳的那块 |
| `--ink` | ink-strong 往 bg 混 9%，保持 ≥7:1 | 4 套实测混比 0/6/9/12% |
| `--ink-soft` | ink 往 bg 混到对比 ≈4.7:1 | 实测 4.6~6.1:1 |
| `--ink-faint` | 同上，目标 ≈2.4:1（装饰性） | 实测 1.5~3.5:1 |
| `--divider` | 同上，目标 ≈1.5:1（装饰性） | 实测 1.21~1.78:1 |
| `--quote-bg` | 默认 bg 与 ink 混 5%（几乎是底色） | 知识风/苔绿/暗夜 ΔE ≤3.5 |
| `--mark-ink` | **条件槽位**：只在字压不住高亮块时**才输出**。深色皮肤必踩 | 暗夜 ink-strong 压亮黄只有 1.47:1 |

> **`accent-soft` / `stage-bg` / `card-shadow` 已经不在这个表里了**（2026-09-30）。
> 派色脚本不再输出它们，皮肤文件也不再手写 —— 前者的默认算法、后两者浅色方案的
> 默认值都下沉到了 `assets/base.css` 块尾。深色底仍要覆盖后两个（`暗夜.css` 有例子）。

「目标对比度」是用二分找混比实现的，不是写死混合比例 —— 同一个比例在深底和浅底上
得到的对比度差得远，按**对比度**定才稳定。想调手感就改 `scripts/lib/palette.mjs` 顶部的 `T`。

#### 两个坑（都不是 bug，是设计）

1. **「面积最大 = 底色」不能当主规则**：配色卡常常是**等面积色块**，这条启发式直接失效。
   所以 `--bg` / `--accent` 是接口的一部分。自动推断照跑，但会标出置信度。
2. **强调色可能被自动加深**：不足 3:1 时保色相压深到 3:1（比如奶油蓝的 `#6b9bc7`
   2.78:1 → `#6294c4` 3.03:1），报告里写明改了哪个值。想保留配色卡原色用 `--no-clamp`
   —— 但先想清楚，这个色管着序号、小标签、引用竖条，压不够就是「印上去等于没印」。

#### 精度（都真跑过）

| 场景 | 结果 |
| --- | --- |
| 纯色块卡取色 | **ΔE = 0**，hex 一位不差（11 张合成卡：等面积 / 单色相梯度 / 深色底 / 12 色相环 / 强调色占 1%） |
| 角色推断（4 套皮肤 × 加权色卡） | 三个关键槽位 **ΔE ≤ 6**，其中 3 套 ΔE = 0 |
| 结构色直取（4 套 × 5 个结构色） | `--no-clamp --merge-e 1` 下 **19/19 一位不差** |
| 自动生成的草稿 | 4 项硬阈值**全过** |
| 压测 7 张极端色卡 | 全部出结果；过不了的必定在报告和草稿里写明「不够」，不静默 |

反直觉但正确的一条：**近色被合并是好事**。知识风的 `#ffffff` 和 `#f7f8fa` 只差 ΔE 2.7，
苔绿的底色和引用块差 4.5 —— 量化器把它们并成一个是对的，不该当成「取色不准」。

#### 其它

- 拿**真实卡片渲染图**取色时，强调色占比常低于默认阈值会被当碎色丢掉：
  放宽到 `--min-share 0.005 --top 10` 才看得见。这也是为什么推荐喂**配色卡**而不是卡片截图。
- `--k` 默认 12，**宁可给大** —— 多余的簇会按 ΔE 合并回去，偏小则会把两色焊死且无法挽回。
- 缩小时**默认不做平滑插值**：开着会在色块交界处凭空造过渡色（实测 4 色卡多出 2 个假色）。
- 颜色数学在 `scripts/lib/color.mjs`，派色规则在 `scripts/lib/palette.mjs`，需要验算直接 import，**别再手写一份 hex→rgb**。

## 字体

| 变量 | 说明 |
| --- | --- |
| `--font-display` | 标题字体 |
| `--font-body` | 正文字体 |

**只能用本机装了的字体**，否则静默降级成难看的默认字体。Windows 安全牌：

```css
"Microsoft YaHei"   /* 微软雅黑，最稳 */
"DengXian"          /* 等线 */
"SimHei"            /* 黑体 */
"SimSun"            /* 宋体，衬线感 */
"FangSong"          /* 仿宋 */
"KaiTi"             /* 楷体 */
```

想用思源黑体 / 思源宋体，得先自己装字体，再写：

```css
--font-display: "Source Han Serif SC", "Noto Serif CJK SC", serif;
```

标题和正文想做出对比，可以一个用衬线一个用无衬线：

```css
--font-display: "SimSun", serif;
--font-body: "Microsoft YaHei", sans-serif;
```

画布宽 1080px，**别拿网页字号来想象**。正文 40px 才是舒服的阅读尺寸。

| `--quote-pad-x` | `44px` | 引用块左右内边距 |
| `--quote-pad-y` | `40px` | 引用块上下内边距 |
| `--quote-bar` | `12px` | 引用块左侧竖条粗细。0 = 不要竖条 |
| `--img-max-h` | `720px` | 单张配图最大高度 |
| `--img-max-h-solo` | `1010px` | 整页只有一张图时，允许放到多大 |
| `--cover-sub-gap` | `44px` | 封面主标题与副标题的距离 |

> **配图边框的三个变量不在皮肤里。** `--img-border-w` / `--img-border-color` / `--img-shadow`
> 由 `assets/frames/*.css` **独占定义**，用 `--frame` 切换。详见下面「配图边框怎么调」。

### 配图边框怎么调

**首选方式：用边框预设，不改变量。**

边框风格单独放在 `assets/frames/` 目录，出图时一行参数切换，不动皮肤：

```bash
node scripts/build-cards.mjs 稿件.md --frame paper     # 相纸框
node scripts/build-cards.mjs 稿件.md --frame none      # 不要边框
node scripts/build-cards.mjs 稿件.md                   # 不写 = 默认 hairline（细描边）
```

也可以在稿件 front-matter 里写 `frame: paper`，整个稿子固定用这个风格。
**命令行 > front-matter > 默认值（`hairline`）**。

| 预设文件 | `--frame` 可用值 | 效果 |
| --- | --- | --- |
| `frames/hairline.css` | `hairline` / `细描边` / `a` | 8px 细线，边框色取 `--divider`。**默认** |
| `frames/paper.css` | `paper` / `相纸框` / `相纸白框` / `c` | 40px 粗边填 `--card-bg` + 投影 |
| `frames/none.css` | `none` / `无边框` | 0px，光边 |

**调参台**里「配图边框（一键切换）」那组按钮，点一下就是这三个预设，实时预览。

> **从调参台导出的配置里，配图边框那三个变量是「整段注释掉」的** —— 导出结果长这样：
>
> ```css
> :root { /* 皮肤变量 */ }
>
> /* ---- 配图边框（整段是注释，故意不生效）----
>    --img-border-w: 40px;
>    --img-border-color: var(--card-bg);
>    --img-shadow: 0 14px 34px rgba(23,32,45,.18);
> -- */
> ```
>
> 原因是这三个变量由 `assets/frames/` 独占（见下）。**写进皮肤文件会把边框色固定成具体色值**，
> 以后换皮肤时边框就不跟着底色走了。注释掉既保住了你调的值（再导入调参台还能读回来），
> 又不会在直接粘贴时误伤皮肤文件。想固定这套边框 → 去改或新建 `assets/frames/<名字>.css`。
>
> 至于 `--img-border-color` 的语义引用：导出时会保留成 `var(--divider)` / `var(--card-bg)`，
> 不会拍平成 hex —— 这是 2026-09-15 实测修掉的坑（修之前导出得到 `#a5c0db` 这种死值）。

#### 三个底层变量

预设文件里就设了这三个变量，想微调就直接改。
**这三个变量由 `assets/frames/` 独占定义，皮肤文件不参与** —— 所以改这里一定生效
（重构前皮肤里也内联了一份一模一样的默认值，导致 `hairline` 预设实际是空转的，改它不生效）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `--img-border-w` | `8px` | 边框粗细，`0` = 无边框。0~12 = 细线，16~24 = 画框，36~48 = 相纸厚边 |
| `--img-border-color` | `var(--divider)` | 边框颜色。写成 `var(--card-bg)` 就是相纸框 |
| `--img-shadow` | `none` | 投影，例 `0 14px 34px rgba(23,32,45,.18)` |

用 `var()` 引用皮肤变量，换皮肤时边框会自动跟着适配，不用改两份。**注意**：`getComputedStyle` 读到的是解析后的色值，不是 `var(...)` 字符串——这是 CSS 自定义属性的规范行为，别以为是 bug。

**加一种新风格**：往 `assets/frames/` 放一个只含这三个变量的 css，文件头部写好
`@frame-meta`（名字/别名/摘要），**代码零改动** —— 别名表、命令行提示、总览页都会自动认它。
（以前要在 `build-cards.mjs` 的 `FRAME_ALIASES` 里手工加一行，容易漏。）

#### 两个必须知道的点

- **边框会占配图自身的宽高**（全局 `box-sizing: border-box`）。粗边框（`paper` 那种）让图变小、占地变大，可能把本来同页的内容挤到下一页——分页器已经把边框宽度算进权重了，所以**只会换页，不会溢出**。
- 边框画在图片内容外，圆角会跟着走，不用额外设置。

## 新建一套皮肤

**不用改任何代码。** 加一个 css 文件就行：

```bash
cd <技能目录>/assets/themes
cp default.css 清晨蓝.css        # 文件名就是皮肤名（不带 .css），中英文都行
```

然后改两处。

**① 文件头部的 `@theme-meta`** —— 这是皮肤的身份，脚本从这里读，别省：

```css
/* @theme-meta
   @name:    清晨蓝
   @slug:    morning           ← ASCII 短名，用于生成产物文件名，别用中文
   @badges:  浅蓝
   @aliases: 清晨蓝, morning, 晨蓝
   @summary: 淡蓝底 + 深蓝强调
   @use:     日常记录 / 轻松话题
   @order:   5
*/
```

**② 下面的 9 行配色。** 字号、间距、字体想改也能写在同一块里（覆盖 `base.css` 的基准值）。

改完直接可用：

```bash
$NODE scripts/build-cards.mjs 稿件.md --theme 清晨蓝
```

或者让稿件自己记住：

```markdown
---
theme: 清晨蓝
---
```

> **为什么身份写在文件里，而不是写在代码里**：以前别名表在 `build-cards.mjs` 里，
> 加一套皮肤要改两个地方，漏一处就会出现「文件加了、但 `--theme` 认不出」这种怪 bug。
> 现在皮肤文件自带身份，别名表、`--theme` 的报错提示、`docs/gallery.html` 总览页
> 全都自动认它；改皮肤名字也只需改这一个文件。
>
> 内置换过名字的皮肤（比如 `知识风` 曾叫「干净深色风」）就是靠 `@aliases` 把旧名字留下来的。
>
> **⚠️ 唯一的例外：`--help` 的 usage 文本是手写的，不跟目录走。**
> `build-cards.mjs` 里那段「`--theme 皮肤（默认 奶油蓝）:`」清单是硬编码的，
> **加/删皮肤后必须同步它**，否则不带参数运行或 `--help` 时列出的清单会骗人
> （2026-10-12 删掉知识风/苔绿时就撞上过这条）。
> 功能本身不受影响 —— `--theme` 传错时的报错清单是**动态读目录**的。

> ⚠️ 做深色底之前先读下一节 —— 只改 `--card-bg` 会得到「深底黑字」，等于看不见。

## 删掉 / 停用一套皮肤或边框

**机制：目录里见 `.css` 就认，没有开关、没有白名单。** `scripts/lib/templates.mjs` 干的就是
`readdirSync(dir).filter(f => f.endsWith('.css'))`。所以「删除」＝把文件移出那个目录。

三种做法，按你想不想留后路选：

| 做法 | 命令 | 结果 |
| --- | --- | --- |
| **移进归档子目录**（推荐） | `mkdir -p assets/themes/_archive` 然后把文件移进去 | 目录名不以 `.css` 结尾 → 自动被忽略。**留档、不删、随时能捞回来** |
| 改扩展名 | `mv 暮紫.css 暮紫.css.off` | 同上，`endsWith('.css')` 为假。想恢复改回来即可 |
| 真删 | `git rm assets/themes/暮紫.css` | 干净。`--theme 暮紫` 会报错并列出所有可用项；git 历史里能找回 |

删掉之后，这套皮肤会从 `--theme` 选项、`docs/gallery.html`、README 预览图里**一起消失** ——
这是对的，因为清单只有一个来源。

> ⚠️ **边框别删 `hairline`。** 它是 `--frame` 的默认值，删掉之后不传 `--frame` 的稿件会找不到默认边框。
> 同理 `--img-border-*` 三个变量由 `frames/` **独占**，所以每个边框文件都**必须把三个变量写全**，
> 少写一个就会漏到上一层的值（或者没有值）。

## 加完 / 删完之后：刷新三样生成物

`docs/` 和 `templates/` 下的三样东西是从 `assets/` 生成的。改了资产不刷新，它们就开始骗人
（历史上 README 出现过「3 张旧皮肤 + 1 张新皮肤」混在一行，就是这么来的）：

```bash
node scripts/build-tuner.mjs     # → templates/tuner-data.js（调参台的清单）
node scripts/build-gallery.mjs   # → docs/gallery.html（总览页）
node scripts/build-preview.mjs   # → docs/preview/*.png（README 门面图）
```

三条顺序无所谓，但**别只跑一条**。

### 总览页里「配图边框」用的是另一把尺子（别改回去）

边框样张和皮肤样张**不是同一个缩放比例**，故意的：

| 区域 | 比例 | 为什么 |
| --- | --- | --- |
| 皮肤 | 19.44%（1080 → 210px） | 配色差异是大面积的，缩到 210px 照样看得出 |
| 边框 | 50%（1080 → 540px） | 细描边只有 **8px**，按 19.44% 缩完只剩 **1.56px** —— 和无边框的 0px 视觉上没区别 |

另外每块边框样张左侧挂一张 **实尺示意（1:1，不缩放）**：一块模拟配图的方框，边框按真实像素画。
缩略图再小，这把尺子是准的，8px / 40px / 0px 一眼可比。

> **2026-10-12 用户反馈「细边框和无边框的示例图看起来怎么差不多」，根因有两层**：
> ① 边框样张的 `.scope` 里只写了边框变量，缺默认皮肤的 `--divider` / `--card-bg`，
> `var()` 解析不到值 → 连 `--card-bg` 都没了 → 三张样张全线隐形（已用 `mergeDecls` 修）；
> ② 修完①之后**还是像** —— 19.44% 的比例把 8px 压成 1.5px，而 `--divider` 对 `--card-bg`
> 的对比度只有 **1.78:1**（浅蓝压奶油）。「相纸框」同理：边框色 = 卡片底色，奶油压奶油。
> **结论：这里是在显示一条线，不是一块色 —— 判断可见性要算「缩完还剩几像素」，
> 不能只看颜色对不对。**

### README 预览图的命名规则（别改回去）

| 文件 | 名字怎么来的 |
| --- | --- |
| `theme-<slug>.png` | 每套皮肤一张封面，`<slug>` 取自该皮肤 `@theme-meta` 的 `@slug` |
| `page-content.png` / `page-figure.png` | 默认皮肤的内容页与配图页，演示的是**版式**不是皮肤，所以名字里不带皮肤名 |

**故意不带序号。** 早先叫 `01-theme-cream.png`，序号是按目录顺序现算的（`i + 1`），
于是「新增一套皮肤」会把后面所有文件挤着改名 —— README 里写的 `05-page-content.png` 那格
被新皮肤的封面占了，**不报错，只是默默显示成另一张图**。静默错图比裂图难发现得多。

现在文件名只由皮肤自己的 `@slug` 决定，加删皮肤互不影响。

`build-preview.mjs` 跑完会**反过来查 README**，三件事：

1. README 引用的图不存在 → **报错退出**（真上线就是裂图）
2. 生成的图没被 README 引用 → 告警（通常是加了皮肤忘了更新 README）
3. 皮肤预览图的 alt 里没提到那套皮肤的名字 → 告警
   （就是「图是细描边、alt 写着相纸白框」那类错）

## 想改总览页这个网页本身的样子

**别混淆两件事**：卡片出图的配色在 `assets/themes/*.css`（`--card-bg`、`--ink` 那一批）；
而 `docs/gallery.html` **这个网页自己**长什么样，是另一套变量，在
**`assets/gallery-shell.css`**（统一 `--gal-*` 前缀）：

```css
/* assets/gallery-shell.css */
:root {
  --gal-page-bg: #f4f5f7;      /* 整页背景 */
  --gal-surface: #ffffff;      /* 面板底色 */
  --gal-ink: #1f2430;          /* 主标题 */
  --gal-ink-faint: #8b93a3;    /* 文件路径、脚注 */
  --gal-ok: #1c7a4a;           /* 对比度 ✓ */
  --gal-warn: #b4761a;         /* 对比度 △ */
  --gal-warnbox-bg: #fff8e6;   /* 黄色告警框 */
  --gal-infobox-bg: #eef6ff;   /* 蓝色说明框 */
  /* …共 22 个，文件里有注释 */
}
```

想换观感：改这个文件 → `node scripts/build-gallery.mjs`。
**不用碰 `build-gallery.mjs`** —— 那边的 `<style>` 现在只写排布与缩放，颜色一律
`var(--gal-*)` 引用。2026-09-17 之前这 20 多个色值硬编码在生成器的模板字符串里，
想调页面颜色必须改 JS，属于「明明是我的东西我却改不动」。

## 深色底皮肤怎么调

内置的 **`暗夜`** 就是一套现成的深色底皮肤，**直接抄它最快**：
`assets/themes/暗夜.css`，实测各项对比度都过阈值。

在它基础上改，记住三条：

**① 那 9 个颜色要整体反过来**，不能只改 `--card-bg`。`--ink` 系列全部换成浅色，
否则就是深底黑字。深色皮肤的 `--ink` 也不建议用纯白，久看刺眼。

**② `--mark-ink` 必须显式设成深色。** 高亮块是「`--mark-bg` 做底 + `--mark-ink` 做字」，
`--mark-ink` 不设时跟随 `--ink-strong` —— 深色皮肤下那是近白色：

```css
--mark-bg: #f2c94c;   /* 亮黄荧光笔 */
--mark-ink: #1b1e24;  /* ⚠️ 深色字。漏了这行就是白字压亮黄 */
```

> 本文档 2026-09-17 之前写的是「深色底要把 `--mark-bg` 换成亮色」——
> 只说对了一半，**漏了字色也得跟着换**。照那句改会得到 1.44:1 的高亮块，
> 肉眼看就是一团黄，字没了。已按上面的写法更正，并把 `--mark-ink` 加进了
> 「对比度自检」的检查项。

**③ `--quote-bg` / `--divider` 是「比底色亮一点」**，
和浅色皮肤「比底色深一点」的思路正好相反。差一点点就够，别拉太开。

**④ `--stage-bg` 和 `--card-shadow` 必须覆盖。** 这两个浅色皮肤已经不写了
（`base.css` 给了默认值），但深底上「比卡片暗一点」需要**大得多的相对步长** ——
浅色皮肤差 6% 就够了，深色皮肤（`#1b1e24` 这类低亮度值）差 6% 肉眼看不出层次。
不写就会看到卡片和背景糊成一片。直接照抄 `暗夜.css` 里那两个值即可。

> `--accent-soft` 不用管了：它现在是「强调色的半透明版」，深浅底都自适应，
> 定义在 `assets/base.css` 块尾。
